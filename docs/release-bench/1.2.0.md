# Release bench 1.2.0: INCONCLUSIVE (gate passed on an off-target set)

**Verdict: INCONCLUSIVE (gate passed on an off-target set).** Both tiers PASS
the gate: Haiku +2.7 points of pass rate at x0.73 cost, Luna -7.3 points
(one-sided bound -15.5 to +0.0, McNemar p = 0.185) at x0.99 cost. No tier
FAILs, so the bench does not stop the release. The Luna point estimate is
below the -5 point margin but not significant, and the gate lists it as a
warning. The A/A run of set v2 (Aether 1.1.0 against itself,
[release-bench-2026-10-18-aa-v2.md](../release-bench-2026-10-18-aa-v2.md))
showed a Luna gap of -10.0 points between two copies of one binary, so a gap
of this size is within this tier's run-to-run noise.

**Luna follow-up: no regression established; the dip fits run-to-run
noise.** Reading the 1.2.0 changes and the run's records found no cause
([Investigation](#investigation)), so no code changed. A Luna-only rerun with
a new seed gave -1.8 points (bound -9.1 to +6.4, McNemar p = 0.851). Pooled
over both runs, the change is -4.5 points (bound -10.5 to +0.9), and the gate
passes with no warning ([Luna rerun](#luna-rerun)). The bound still admits a
loss larger than the 5-point margin, so the bench cannot rule one out either.

Produced by `make bench-release OLD=<aether 1.1.1> ALLOW_OFF_TARGET=1` with
the default set, arms (Haiku and Luna tiers, no Archon arm), `JOBS=6`,
`LOAD_MAX=16`, and `BUDGET=20`, raised to 30 for the last resume (below); see
[release-bench.md](../release-bench.md).

## How the run went

- **First attempt, an infrastructure failure.** The bench drives every Aether
  arm through this tree's Python client, whose hello asked only for protocol
  24. Aether 1.1.1 serves 17 to 23, so all 18 old-arm trials were refused at
  the handshake (`incompatible: client protocol 24 is not served`), counted as
  harness failures and charged their whole reservation, and the budget
  stopped the run after 52 trials. Fixed by letting the bench's client
  reconnect at the newest version both sides serve (`fix(bench): reach the
  last release's daemon after a protocol bump`); its report is not a verdict.
- **The rerun** under a new run id ran 654 trials in 120 minutes and was then
  stopped from outside by a time limit of the session running it. No trial
  process was left behind.
- **Two resumes** under the same run id. The first moved the 4 interrupted
  trials aside and charged their reservations ($10.54), which brought the
  counted spend to $19.53 and stopped it at `BUDGET=20` before any trial. The
  second, at `BUDGET=30`, ran the last 6 trials. The budget is not part of a
  run's configuration, so the resume kept the same matrix, binaries and seed.
  The run's priced spend is $9.14; the whole run took about 125 minutes. The
  header's wall time below covers the last resume only.

## Investigation

The Luna point estimate was 7.3 points below the old release, past the
5-point margin. Before running the tier again, the 1.2.0 changes were read for
a cause, and the run's per-trial records (`results.jsonl` of
`rel-1.2.0-vs-1.1.1-r2`; the trial directories were gone) were checked for
one. Neither shows one.

**The code.** The diff `v1.1.1..466874da` was read for everything that reaches
a Codex agent:

- **The Codex driver and its app-server protocol use.** `codex_app.rs` only
  registers the engine's pid for orphan reaping (#203) and drains stderr
  through the turn's redactor. The launch arguments, `-c` overrides, effort
  setting and app-server requests are unchanged; `codex_app/` changed only
  in a test.
- **The agent's MCP bridge** (`aether-engine/src/bridge*`) is unchanged.
  The JSON-RPC rules of #217 are in `aether mcp serve`, the operator surface,
  which no bench agent uses.
- **The system prompt and the tool list.** `aether-engine/src/contract*` and
  context rendering are unchanged, apart from a test. Among the harness tools only
  `complete_task`/`fail_task` changed: input checks (#206 payload bounds, #207
  `structured: null` taken as absent). #216 reverted the one description
  change #207 made, so the tool surface the model reads is the 1.1.1 text.
  `inspect_state` now also reports limits, but only when called.
- **Turn-ending tools (#206).** After `complete_task`, `fail_task` or a wait
  has ended the turn, a sibling call that starts work or delivers an effect
  (`delegate` without a wait, `send_message`, `remember`, schedules,
  `integrate_workspace`) is refused. Codex's own shell and patch tools are
  not harness actions and are not touched. A solo task's edits come before its
  `complete_task`, so the refusal cannot undo or block them.
- **Redaction (#187, #215).** A native engine's tool result is masked in
  `turn_engine/events.rs` before Aether *stores* it. Codex runs its shell
  itself and reads the raw output, and a bridge reply goes back to Codex
  before the stored copy is masked. Engine stderr and error text are masked
  in the record only. Redaction changes the record, never what Luna reads.
- **Budgets, retries and timeouts.** The scheduler's budget check now reads
  only budgeted agents (#197) and words its message differently (#212). The
  Luna arms' cap (4M tokens) and the 600 s trial timeout are unchanged. No
  engine retry or timeout changed.

**The records.** All 330 Luna trials finished `completed`, with no
infrastructure error, harness failure, spend stop or timeout, on either
binary. 18 tasks passed on 1.1.1 only, 10 on 1.2.0 only. The 18 do not
share a cause:

- They spread over 7 of the 9 families: edgecase 5, docspec 4, algo 2,
  refactor 2, port 2, longctx 2, traceback 1.
- They are mostly near misses. The failing 1.2.0 trial missed 1 hidden check in
  7 tasks and 2 in 6; only `pricing-2` (0/10), `batching-7` (2/9) and
  `diff-6` (3/10) missed most checks. The 10 reverse flips look the same: one
  check missed in 6 of them.
- 1.2.0's failing trials did not stop early. On those 18 tasks the median is
  33 s and 179k tokens for 1.2.0, against 35 s and 149k for 1.1.1. Over the
  whole tier, 1.2.0's median is 41 s and its mean 309k tokens, against 42 s
  and 299k for 1.1.1. No Luna trial was cut by the token cap; the largest,
  `query-7` on 1.2.0 at 3.9M tokens, failed on 1.1.1 too.

Luna at low effort varies a lot from run to run. In every run so far, 25 to
37 % of the tasks gave different results on the two Aether arms of the tier.
The two A/A runs, where both arms were one binary, went +2.2 points (set v1,
discordant 16 old-only / 18 new-only) and -10.0 points (set v2, 24 / 13).
Issue #221 (a Codex agent said `complete_task` was not offered) does not show
here: every Aether Luna trial of both binaries ended `completed`. With no
cause in the code or the records, no code was changed, and the tier was run
again.

### Both Luna runs pooled

Method: the Luna records of both runs (`rel-1.2.0-vs-1.1.1-r2` and
`rel-1.2.0-vs-1.1.1-luna-r3`) are joined with each run as one repeat of
every task, and the bench's own `release_bench_stats.gate` is applied. That
gives the report's numbers: each task's two cells per arm are averaged, a
paired bootstrap over the 110 tasks gives one-sided 95 % bounds, and the
margins are 5 points and 15 %. The McNemar count adds the 220 matched cells
and treats a task's two cells as independent, so its p-value is somewhat
optimistic. The bootstrap is the figure to read. A short script outside the
repository computed it; it reproduces the first run's report exactly.

| | luna/old | luna/new | Pass, new - old [one-sided 95 % bound] | McNemar old-only / new-only, p | Cost new/old |
|---|---:|---:|---|---|---|
| First run (seed 0) | 58/110 | 50/110 | -7.3 [-15.5, +0.0] | 18 / 10, 0.185 | x0.99 |
| Rerun (seed 1) | 51/110 | 49/110 | -1.8 [-9.1, +6.4] | 15 / 13, 0.851 | x1.11 |
| **Pooled** | 109/220 | 99/220 | **-4.5 [-10.5, +0.9]** | 33 / 23, 0.229 | x1.05 [x0.93, x1.18] |

Pooled, the gate passes Luna without a warning. The point estimate is
inside the 5-point margin, and the interval includes zero. **No regression
is established, and the first run's dip is consistent with run-to-run
noise:** no cause in the code or the records, a rerun at -1.8 points, and a
pooled -4.5 points that is not significant. The data do not rule a regression
out: the pooled bound, -10.5 points, still admits a loss larger than the
5-point margin. Narrowing it would take more repeats of the tier.
