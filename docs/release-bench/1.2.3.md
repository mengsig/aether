# Release bench 1.2.3: no decrease (Luna dip not confirmed)

**Verdict: no decrease.** Haiku is **+0.9 points** against 1.2.2 (one-sided
95% bounds -2.7 to +5.5, McNemar p = 1.000; old-only 3, new-only 4) at x1.00
cost. Luna's first run read **-9.1 points** (-17.3 to -0.9, p = 0.099;
old-only 20, new-only 10), which meets the release rule's decrease test
(p < 0.1 with the interval below zero), although the bench's own gate passed
it with a warning. The confirming Luna rerun with a new seed gave **+3.6
points** (-4.5 to +11.8, p = 0.597). Pooled over both runs Luna is **-2.7
points** (-8.6 to +3.2, p = 0.526) at x1.03 cost, and the gate passes with no
warning. The decrease is not confirmed, and cost per trial shows no increase
beyond noise (pooled Luna x1.03, interval x0.91 to x1.17). The set is off
target, so each run's verdict reads INCONCLUSIVE; the gate itself passed. No
trial had an infra error or a harness failure.

What the per-trial records show:

- Haiku: 7 tasks differ, and every one misses one or two checks of its task.
  Only on 1.2.2: `exporters-0` (5/6), `ledger-0` (9/11), `versions-9`
  (10/11); only on 1.2.3: `exporters-8`, `query-7`, `versions-0`,
  `versions-7`.
- Luna, first run: 7 of the 20 old-only tasks are `pricing` (1.2.2 9/11,
  1.2.3 4/11). 1.2.3 missed one to three hidden coercion or generated-order
  checks there (typically 8/10). The trials had the same shape on both arms:
  one turn, a similar number of tool calls (mean 9.2 against 9.7, median 7
  on both), no stall and no new event apart from one `budget.warning` on
  `versions-2`, which both arms failed.
- Luna rerun: the flips did not come back. Of the first run's 20 old-only
  tasks, 5 were old-only again (`config-6`, `cron-6`, `pricing-10`,
  `pricing-7`, `slug-3`), and 1.2.3 passed 11 of the 20. `pricing` went 6
  (1.2.2) against 7 (1.2.3). One 1.2.3 trial, `versions-4`, ran to the arm's
  4M-token cap and Aether stopped it there, as configured; its usage stayed
  unpriced, so the rerun's cost comparison covers 109 tasks.
- Changes between 1.2.2 and 1.2.3 that reach an agent: none in its prompt or
  tools. Engine CLIs and tool commands start with default signal
  dispositions, each engine carries a reaping token, the Codex session event
  lists the offered tools once known, a direct user message records
  `reply.owed`, and a silent turn is stopped after 15 minutes (no trial
  reached it). The hard stop is off unless configured.
- Claude Code 2.1.306 and Codex 0.163.0 on both arms, as for r122.

### Both Luna runs pooled

The Luna records of `r123` and `r123-luna-s1` are joined with each run as one
repeat of every task, and the bench's own `release_bench_stats.gate` is
applied: each task's two cells per arm are averaged, a paired bootstrap over
the 110 tasks gives one-sided 95% bounds, and the margins are 5 points and
15%. The McNemar count adds the 220 matched cells and treats a task's two
cells as independent, so its p-value is somewhat optimistic; the bootstrap is
the figure to read. A short script outside the repository computed it, and it
reproduces r123's own Luna numbers exactly. Pooled, the point estimate is
inside the 5-point margin and the interval includes zero. The pooled bound,
-8.6 points, still admits a loss larger than the margin, as in 1.2.0;
narrowing it would take more repeats of the tier.
