# Release check 1.4.2 (post-release): full bench vs v1.4.1

**RESULT: NO REGRESSION by the release gate (Haiku PASS, Luna PASS).**

**Caution on Luna:** the pass-rate point estimate is -5.5 points (42/110 vs
48/110), past the -5 point warning line the harness prints. It is not
significant (McNemar p = 0.418; interval [-14.5, +3.6] points), so the gate
passes, but the data cannot exclude a Luna loss of up to 14.5 points.
Haiku shows no change (103/110 in both).

Raw command verdict: `INCONCLUSIVE (gate passed on an off-target set)`; the
command exits nonzero on this set by design, as in [1.3.1](1.3.1.md).
`ALLOW_OFF_TARGET=1` was set. This is the first full bench of the 1.4 line;
1.4.0, 1.4.1 and 1.4.2 had run only the 10-task smoke.

## Setup

- NEW: published v1.4.2 Linux x86_64 musl archive; OLD: published v1.4.1.
  Both downloaded into fresh temporary directories and verified against the
  release `SHA256SUMS`; extracted binaries report `aether 1.4.2` and
  `aether 1.4.1`.
- Source tree: `origin/next` at `48669d5ac` (the 1.4.2 release).
- `make bench-release OLD=... NEW=... ALLOW_OFF_TARGET=1 JOBS=6 LOAD_MAX=16
  BUDGET=40`, run directly (the host CI slot was held by another bench).
  Set `bench/release-set/v2`, 110 tasks, sha256 `7f3166c96e35e2ad`; native
  CLIs claude 2.1.325, codex 0.169.0; one repeat; timeout 600s.
- 660 of 660 trials completed in one invocation (158.4 min), no resume, 0
  infra errors, spend USD 8.90 API-equivalent. One harness failure
  (`haiku/old` `cron-1`, which was still graded). Timeouts (600s, graded as
  recorded): `luna/new` versions-0; `luna/old` workstreams-7, workstreams-8.

## Luna confirmation (subsample)

**VERDICT: UNCLEAR, leaning REAL.** The Luna drop did not vanish on fresh
trials: the new arm lost again, by a larger margin, but not significantly.

Method: the 38 Luna tasks above that differ between v1.4.1 and v1.4.2 (22 old
only, 16 new only) ran again on `luna/old` and `luna/new` only, 2 fresh
repeats per (task, arm): 152 trials, `--jobs 4`, `LOAD_MAX=16`, low effort,
timeout 600 s, the same published musl binaries (SHA256SUMS verified) and the
same set bytes (a 38-task copy of `bench/release-set/v2` with its task files
unchanged). Run in a private HOME holding copies of the engine credentials,
deleted afterwards. Harness and set are untouched in git.

| Fresh, 38 tasks | Passed / 76 | Rate [Wilson 95%] |
| --- | ---: | ---: |
| luna/old | 41 | 54% [43%, 65%] |
| luna/new | 31 | 41% [30%, 52%] |

- Paired by (task, repeat): new minus old -13.2 points, McNemar old-only 21 /
  new-only 11, p = 0.110; task-level bootstrap interval [-27.6, +1.3].
- The 22 "old only" tasks (44 pairs): old 26, new 18 (15 / 7, p = 0.134). The
  old arm's lead reproduces, softened.
- The 16 "new only" tasks (32 pairs): old 15, new 13 (6 / 4, p = 0.754). The
  new arm's edge does not reproduce; they regress to about even, slightly
  toward old. Pure noise would have put both groups near even.
- Families, new vs old passes of (task, repeat) pairs: algo 4 vs 6 of 6,
  longctx 0 vs 2 of 2, refactor 2 vs 4 of 6, traceback 1 vs 3 of 4, docspec 9
  vs 13 of 26, port 7 vs 6 of 10, edgecase 8 vs 7 of 22. The losses sit in
  algo, longctx, refactor, traceback and docspec; port and edgecase are even.
  These cells are small. Per-task grid: `.archon/reports/bench/index.html`
  (published as an artifact).
- Combined with the original run (3 trials per arm on these 38 tasks, 1 on
  the other 72, which agreed): adjusted overall new minus old -4.8 points
  [-10.3, +0.3], against -5.5 originally. The 38 tasks were picked because
  they disagreed, so this mixes selected and unselected data; read it as
  rough.
- Reading: the first run was not just a weird run, and the evidence does not
  show a real loss either. The fresh point estimate (-13 points) is consistent
  with a true loss of a few points up to about 14, or with no loss. Settling
  it needs the whole set repeated with more repeats,
  which was not run.
- Spend: USD 0.62 API-equivalent, 24.5M tokens, 152 of 152 trials completed,
  no rate limiting seen (the harness does not expose Codex quota). One
  harness-level notice: a daemon cleanup timeout after `luna/old` `ledger-2`
  r1, graded normally.
