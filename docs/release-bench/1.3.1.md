### Fresh v1.3.0 comparison

The stored timing baseline was recorded without its load guard near load 25.
The initial local-index measurement above was 29.2%, 58.6%, 31.6% and 47.3%
slower than that baseline (dataset median/p95, scaled median/p95). Those
machine-dependent differences do not establish a release regression.
Per the amended rule, the gate uses fresh same-session v1.3.0 measurements
and a 10% slowdown threshold instead.

Both pinned drivers ran the same local-index plan (30 repetitions per query,
48 seeded memories and 5,048 scaled memories), in order old/head/old/head,
under one host slot. Each run waited for 1-minute load <=10. Times below are
milliseconds; loads are 1-minute averages at start and end.

| Run | Arm | Load start -> end | Dataset median | Dataset p95 | Scaled median | Scaled p95 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 1 | v1.3.0 | 9.74 -> 10.51 | 2.903659 | 6.840002 | 14.473426 | 31.236331 |
| 2 | head | 7.49 -> 7.18 | 2.528570 | 3.546454 | 9.951852 | 14.372141 |
| 3 | v1.3.0 | 7.18 -> 6.62 | 2.547158 | 3.885466 | 10.731411 | 16.709193 |
| 4 | head | 6.62 -> 6.96 | 2.530842 | 3.954138 | 10.439853 | 16.036035 |

The first old run was noisier and the gate held the following head run for
90 seconds. The closest-load second pair is decisive: head changes -0.6%,
+1.8%, -2.7%, -4.0%, respectively. The only slowdown is dataset p95 +1.8%,
within the allowed 10%. Means over both runs per version change -7.2%,
-30.1%, -19.1%, -36.6%. No latency DECREASE under the amended rule.
All paired runs have identical storage metrics. No benchmark code, dataset,
threshold or prompt was changed to improve these results.
