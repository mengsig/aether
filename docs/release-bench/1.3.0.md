# Release bench 1.3.0: no decrease

**Verdict: no decrease.** Haiku is **-1.8 points** against 1.2.11 (one-sided
95% bounds -5.5 to +1.8, McNemar p = 0.688; old-only 4, new-only 2) at x1.00
cost (x0.93 to x1.05). Luna is **-8.3 points** (-17.4 to +0.9, p = 0.175;
old-only 22, new-only 13) at x0.91 cost (x0.80 to x1.01). Neither tier meets
the release rule's decrease test (p < 0.1 with the interval below zero), and
neither cost interval lies above x1.00, so no cell was repeated. Neither tier
failed the gate. It warned on Luna's pass point estimate (below -5%). The
gate reads INCONCLUSIVE on both tiers rather than passed, because one block
of the matrix did not run ([below](#the-unfinished-block)). The set is off
target too, so the run's verdict reads INCONCLUSIVE.

**Luna's point estimate is within the set's noise, but it is the largest
final step in the [chained table](history.md#chained-per-release-results-for-context),**
beside [1.2.7](1.2.7.md)'s -8.2 (p = 0.175) against 1.2.6.
The A/A check of set v2
([release-bench-2026-10-18-aa-v2](../release-bench-2026-10-18-aa-v2.md)),
the same binary on both arms, measured Luna at -10.0 points (p = 0.099).
Here the flips run both ways inside the same templates (`duration` 3 to 4,
`config` 1 to 2, `cron` 3 to 1, `exporters` 2 to 2), and 14 of the 22
old-only tasks missed one or two hidden checks on 1.3.0. The check fraction
moved -2.3 points (-5.5 to +1.1). No Luna trial on either arm was a harness
failure or an infrastructure error. Native Luna passed 43% in the same run,
between the two Aether arms (1.2.11 50%, 1.3.0 41%).

## Luna cost: first turn against later turns and retries

Archon 1.5.0's own release check saw Luna cost rise 31% per run on Aether
1.3.0, all of it in review repairs. This bench has no review and no repair:
each trial is one Aether agent given one task, with no Archon arm
(`ARCHON_BIN` unset). The closest split its records hold is per turn: each
trial's `usage_report` lists every turn of every agent with its cost, and
each turn's process attempts. Below, "first turn" is the root agent's turn 1,
"later turns" its turns after that (a wake-up after a child reports, say),
"children" every delegated agent, and "retried attempts" the turns that
needed more than one engine process.

| Arm | Cost / trial | Root first turn | Root later turns | Children | Trials with a later root turn | Trials with a retried attempt |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| luna/old (1.2.11) | $0.00569 | $0.00496 | $0.00018 | $0.00054 | 5 of 110 | 0 |
| luna/new (1.3.0) | $0.00493 | $0.00435 | $0.00014 | $0.00044 | 5 of 109 | 0 |

**Aether 1.3.0's Luna cost and wall time are not worse than 1.2.11's.** Over
the 109 paired tasks, Luna cost $0.538 on 1.3.0 against $0.594 on 1.2.11
(-9%; the gate's paired ratio is x0.91, x0.80 to x1.01), and every part of
the split is lower, not only the total. Neither binary retried an engine
process on any Luna trial. The median trial took 51.1 s against 50.5 s
(+0.6 s), the mean 69.0 s against 74.9 s, and the summed solve time
125.3 min against 135.6 min. So the 31% rise Archon saw does not show in a
single Aether agent's work on this set. This bench cannot tell whether it
comes from Archon's review and repair loop on 1.3.0. Native Codex has no
per-turn record, so luna/native is left out of the split.

## How it ran

Run `r131` on `9edc9d1f` (tree `43eb0c9c`), the head of #414 with every
vNext task and the 1.3.0 version bump, after `make ci` passed on that head
(6794 passed, 46 skipped, no flaky test), against the v1.2.11 release
binary, with
`make bench-release OLD=<aether 1.2.11> NEW=<aether 1.3.0> ALLOW_OFF_TARGET=1 EXTRA=--run-id=r131`,
that is
`python3 evals/release_bench.py run --set bench/release-set/v2 --old <aether 1.2.11> --new <aether 1.3.0> --arms all --jobs 6 --load-max 16 --budget 20 --repeats 1 --allow-off-target --run-id r131`,
under `scripts/ci_slot.sh`.
The commit that adds this page changes documentation only, so the candidate
is also the release head's code. The candidate is `make build`'s release
build of that head, which `make ci` had just built. The engine CLIs ran in a
private home holding only copies of their logins, with an otherwise empty
environment apart from `PATH`, `TMPDIR`, `LANG` and `XDG_RUNTIME_DIR`. No
operator-level instructions or settings reached any arm. Before the trials,
Codex's app-server was started once in that home for 8 s with no request,
so that its state database exists. No trial hit the state-database error
r128 recorded. The home was deleted after the run.

A first start was stopped about 20 s in, because its shell could not
outlive the two-hour limit of the session that launched it. It had started
the six arms of `cron-8` and recorded no result. That start was discarded
and `r131` run again from the start under the same id, detached from the
session.

### The unfinished block

655 of the 660 planned trials ran. Only luna/old ran `workstreams-8`, the
last block. The run stopped admitting trials at its USD 20 budget with
$6.44 spent: Haiku's reservation for a delegation trial is $13.70 on this
run's price table, which no longer fit beside what was spent. The
reservations are about twice what [the bench page](../release-bench.md)
states (a solo Aether Haiku trial reserves $3.14, not $1.54), because the
pinned table prices a larger worst-case call. Every gate pairs only the
cells both arms counted, so the 109 pairs above are complete pairs. One more
pair moves a tier's pass difference by at most 0.9 points (1/110). Neither
tier's upper bound (+1.8 for Haiku, +0.9 for Luna) can then reach the -5
point FAIL line, and the cost bounds stay far below x1.15. So the missing
block cannot turn either tier into a FAIL. The block could not be finished
by resuming with a larger budget, because Codex had changed version (below)
and the run refuses a resume whose native CLIs differ.

### Engine versions

Claude Code 2.1.316 ran every Haiku trial. Codex updated itself from 0.166.0
to 0.167.0 at 02:15:45 UTC, about ten minutes into the run, outside the
bench's control. The run pinned the version it saw at its start, so the
report below names 0.166.0. By start time, the first 8 Luna trials of each
Luna arm ran on 0.166.0 and the remaining 101 or 102 on 0.167.0. The arms
of a block run back to back, and no luna/old and luna/new pair straddles
the update, so each pair ran on one Codex version.
