# Release bench 1.2.1: no decrease, within noise

**Verdict: no decrease: within noise.** The Haiku drop first seen in r121
(-6.4 points) did not repeat. Pooled over the three Haiku runs (361 paired
trials), 1.2.1 is **-1.1 points** against 1.2.0, one-sided 95% bounds
-3.8 to +1.4, McNemar p = 0.608 (old-only 19, new-only 15). The lower bound
clears the -5 point margin, so a loss that large is ruled out at 95%. Both
tiers pass the gate in the final run on the release head (r121f). The set is
off target, as before, so every run's verdict reads INCONCLUSIVE; the gate
itself passed each time.

| **Pooled** | | **361** | **340** | **336** | **19 / 15** | **0.608** | **-1.1 [-3.8, +1.4]** |

Harness failures are kept apart from agent failures: each run with one
counts a trial whose task passed every check as failed, because the trial
daemon did not stop within 10 s (`daemon_cleanup_error`): `pricing-9` (new)
in r121 and `protocol-3` (new) in r121h3; r121f has none. With those pairs
left out, the pooled difference is -0.6 points [-3.1, +2.0], McNemar
p = 0.860 (old-only 17, new-only 15, 359 pairs). No run had an infra error.

How the runs pool. Every run uses the v1.2.0 release binary (aether sha256
`36cee796b1524c19`, checked against the release's `SHA256SUMS`), the same
frozen set (`bench/release-set/v2`, sha256 `7f3166c96e35e2ad`) and the same
native CLIs (claude 2.1.299, codex-cli 0.163.0). The candidates differ only
outside the agent's reach: `96cfaad0` (r121's candidate binary, sha256
`77958926cb3283d2`) and `438a4093` differ only in `crates/aether-tui`, the
TUI's new crate dependencies (`image` and its decoders, new entries in
`Cargo.lock`, no version of an existing crate changed), scripts and docs,
from #232 and #234. Nothing that builds an agent's prompt, tools or driver
changed, so the three runs measure the same agent-facing code. The pooled
difference weighs every pair equally and resamples tasks within each run
(20,000 draws). r121's per-trial records were not kept, so it enters through
its recorded counts (110 pairs, 10 old-only, 3 new-only); with one repeat per
task its pairs are its tasks, and its interval reproduces the recorded one
exactly. Repeats of one task in r121h3 resample together.

The losses do not cluster. `exporters`, which lost 4 tasks in r121, gained 3
in r121f, and the differing tasks of each run mostly miss a single check of
their task.
