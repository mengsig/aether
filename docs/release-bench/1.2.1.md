# Release bench 1.2.1: INCONCLUSIVE, Haiku pass rate 6.4 points lower (not significant)

**Verdict: INCONCLUSIVE (gate passed on an off-target set), with a Haiku
decrease to report.** Both tiers PASS the gate, but the Haiku tier's pass rate
is **-6.4 points** against 1.2.0 (one-sided bound -11.8 to -0.9, McNemar
p = 0.092; old-only 10, new-only 3), below the -5 point margin, and the gate
lists it as a warning. Luna is +1.8 points (p = 0.875) at x1.01 cost; Haiku
cost is x0.91. The release was **not** investigated further or rerun, per the
operator's rule to report a performance decrease and stop.

What the per-trial records show for Haiku (`haiku/new` against `haiku/old`):

- 13 tasks differ: 10 pass only on 1.2.0, 3 only on 1.2.1. Every 1.2.1 loss
  but one misses a single check of its task: `exporters` (4 losses, 1 gain),
  `query` (3 losses, 1 gain), `workstreams-7`, `versions-7` (a gain).
- `pricing-9` passed all 10 checks on 1.2.1 and is counted as a failure by
  the harness only: the trial daemon did not stop within 10 s
  (`daemon_cleanup_error`). Without it the point estimate is -5.5 points.
- Native Haiku moved -2 to +2 points between the two runs on these tasks, and
  set v2's A/A noise is large, so a loss of this size is not shown to be real.
  Nor is it ruled out: the bound admits a loss beyond the margin.
- Changes between 1.2.0 and 1.2.1 that reach an agent: the `notify` tool
  (a new entry in the tool surface) and the notification center. No prompt or
  driver change.

Produced by `make bench-release OLD=<aether 1.2.0> ALLOW_OFF_TARGET=1` with the
default set, arms and flags (`JOBS=6`, `LOAD_MAX=16`, `BUDGET=20`); see
