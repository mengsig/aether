# 1.3.0 focused coding smoke

This check reuses the 15 task IDs from `ab-haiku-c`, with three repeats per
arm and seed 0, fixed before the run. The set was selected from earlier
Haiku discordances and controls; it is not representative of the full
release set. Each trial starts with an empty private store. No tasks, graders,
prompts, seeds or thresholds were changed for this run.

The candidate was built from `beb6aeeb65edbc9b3ab4e1384bb5654f37f8305e`
(SHA-256 `584a0f1899124e8dd187461669baa29bcdf20384e735b85ed892d9a717c7908f`),
after the holdout changes. Later commits before this report
change only documentation and test-only instrumentation. The old release
binary SHA-256 was `f8bc883d8ba18390a81feed2d1fd7d6cfa858aad65f1dae47fc2a72be7c82835`.
Claude Code 2.1.319 and Codex 0.167.0 were pinned. The trials ran with four
workers, the standard 600-second timeout and load gate 12; no whole run was
repeated.

Of 45 pairs, both passed 35, both failed 1, old alone passed 2 and candidate
alone passed 7. The exact two-sided McNemar p is 0.180; the candidate/old
cost ratio is 0.98. The candidate's observed advantage is not statistically
distinguishable from noise at conventional thresholds; this focused set
cannot establish the absence of a release-wide regression. The report's
release gate is INCONCLUSIVE because only 15 distinct tasks were paired.

One old trial (`query-6` r0) and one candidate trial (`query-5` r0) passed
all hidden checks but were counted as failures when their private daemons
missed the 10-second shutdown window. Both are included above. Excluding
both pairs leaves 43 pairs: old 36, candidate 41; old-only 1, new-only 6,
exact p = 0.125. This sensitivity view does not replace the counted result.
The release report describes the same shutdown issue on both binaries.

The original runner counted `query-5` r0 and `exporters-6` r0 as harness
failures when concurrent first starts could not initialize the private Codex
state database. Neither reached the model; they are infrastructure errors.
After the database existed, the orchestrator authorized one retry of each
same task and repeat with the same binary and seed. Both reached the model
and failed: `query-5` passed 9/12 checks and `exporters-6` 5/6. There were
no further retries. The original records remain intact. One other trial,
`versions-1` r2, used the full 600-second timeout and failed its checks.

The original confirm cost $0.301 and the two retries $0.008. The previous
5/15 and current 19/45 sensitivity result are an unpaired comparison with
unequal repeats and a selected set; their difference is not a release-wide
accuracy estimate. In the broader prior run, the candidate passed 57/110
against 56/110 on v1.2.11. The small confirm does not show an obvious collapse,
but cannot establish parity with that broader result.

## Default behavior compared with v1.2.11

- **Memory retrieval:** the default relevance cutoff and holdout are both
  off. A stale-marked memory scores lower; a pinned file-sourced note whose
  source disappears is marked stale; previously it was left untouched. These
  changes can affect which existing memories the model sees. After the cutoff
  was disabled, the earlier check regained its deterministic baseline for
  retrieval and injection, but its dataset has no file-sourced memories and
  cannot measure that stale-mark path. The coding smoke had empty stores.
  Keep the remaining mechanism; neither check attributes a coding loss to it.
  This is not proof of its populated-store effect.
- **Memory admission and consolidation:** candidate admission is implemented
  but the default mode is `Immediate`; consolidation is operator-invoked.
  Neither changes what this smoke's model saw by default. Keep both available.
- **Native tool bounds:** an outstanding tool call is stopped after 15
  minutes; Claude's shell timeout setting is 600 seconds, matching the
  effective CLI default used here. The smoke has a 600-second trial timeout,
  so it did not measure the 15-minute bound. Keep the hang protection.
- **Prose completion:** a task result expressed as a JSON object in prose can
  retain its structured result. The model request is unchanged; handling
  changes after completion. Prior evidence found 11/43 such completions on
  the candidate versus 2/21 on the old release. Keep the completion fix;
  the smoke does not isolate its effect on coding accuracy.
