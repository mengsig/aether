# Release bench 1.2.10: no decrease (Haiku only)

**Verdict: no decrease.** Haiku is **-1.8 points** against 1.2.9 (one-sided
95% bounds -6.4 to +2.7, McNemar p = 0.754; old-only 6, new-only 4) at x1.11
cost (x0.70 to x1.76). That does not meet the release rule's decrease test
(p < 0.1 with the interval below zero), and the cost interval holds x1.00,
so cost did not rise beyond noise and no cell was repeated. The gate passed
with no warning: the cost point estimate is below its x1.15 warning line.
The set is off target, so the run's verdict reads INCONCLUSIVE.

**Luna not run: Codex quota exhausted; operator approved a Haiku-only
release; the Luna regression check runs at the first release after Codex
returns.** Only the arms `haiku/old` and `haiku/new` ran; no native arm and
no Codex model.

**Haiku's cost rise is two trials' model behaviour.** In `pricing-6` the candidate's Haiku solved the task (10 of 10
hidden checks) and then kept rewriting the tests in one native turn of 53
model calls until the spend guard stopped it at the $0.50 allowance, a
harness failure; 1.2.9 finished the same task in 14 calls for $0.026. The
`pricing` template swings this way on both binaries: 1.2.9's `pricing-7`
spent $0.497 where 1.2.10 spent $0.119, and `pricing-5` $0.274 against
$0.027, so the template as a whole is x1.00. In `workstreams-7` the
candidate's root delegated its four children to
`claude-code/claude-sonnet-5-5` where 1.2.9's root chose Haiku, $0.265
against $0.022 for the same tokens (480k against 473k), as `workstreams-5`
did in [1.2.6](1.2.6.md). Without `pricing-6` Haiku is x0.93, the median
paired ratio is x1.04, and every template other than `workstreams` lies
between x0.92 and x1.11. The one change in 1.2.10 that an agent can see,
the wake after a native answer given while background jobs run (#367),
reached no trial: no trial's events hold its notice. Nothing else the model
sees changed between the two binaries, so no rerun was made.
