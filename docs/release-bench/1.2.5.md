# Release bench 1.2.5: no decrease, Luna cost rise was noise

**Follow-up:** the Luna cost rise did not reproduce. A rerun of the same two
binaries, r125b, measured x0.98 (x0.89 to x1.07), and the candidate sends
Codex the same requests as 1.2.4 ([Luna cost follow-up](#luna-cost-follow-up)).

**Verdict: no decrease.** Haiku is **+0.0 points** against 1.2.4 (one-sided
95% bounds -4.5 to +4.5, McNemar p = 1.000; old-only 4, new-only 4) at x1.29
cost. Luna is **-0.9 points** (-10.0 to +7.3, p = 1.000; old-only 17,
new-only 16) at x1.14 cost. Neither tier meets the release rule's decrease
test (p < 0.1 with the interval below zero), so no cell was repeated. The
gate passed on both tiers; it warned on Haiku's cost point estimate (above
x1.15). The set is off target, so the run's verdict reads INCONCLUSIVE.

**Cost per trial rose.** Luna x1.14 (x1.00 to x1.30) is spread over most
families: without the 11 `pricing` tasks it is x1.23 (90% bootstrap x1.08 to
x1.38), and the median Luna trial used 136k tokens against 118k, while the
candidate's event counts (tool calls, turns, messages) are only 3-5% higher.
Haiku x1.29 (x0.96 to x1.66) comes almost entirely from those 11 `pricing`
tasks, which run for minutes and vary widely (x1.77 there); without them it
is x1.03 (x0.99 to x1.06), and its median paired ratio is x1.00.

What the per-trial records show:

- Haiku: 8 tasks differ. Only on 1.2.4: `diff-5`, `exporters-3`, `query-0`,
  `protocol-7`; only on 1.2.5: `exporters-0`, `exporters-1`, `exporters-5`,
  `query-6`. The cost ratio comes from three `pricing` trials of the
  candidate (`pricing-0`, `-4`, `-8`, together $0.87 against $0.18), each a
  pass that ran 5 to 9 minutes; `pricing-5` went the other way ($0.02
  against $0.12).
- Luna: the flips spread over the families in both directions. `docspec`
  went the candidate's way (1.2.4 21%, 1.2.5 36%), `port` the old binary's
  (91% against 64%). Every Luna trial completed and was priced; median
  times were 26 s (1.2.4) and 28 s (1.2.5).
- One harness failure: the 1.2.4 daemon of Haiku's `versions-1` trial did
  not stop within 10 s at cleanup. The trial had passed 11/11 checks and is
  graded a loss; the candidate failed it too (9/11), so the pairs are
  unchanged. No trial had an infra error.
- Changes between 1.2.4 and 1.2.5 that reach an agent: the `delegate` tool
  takes an `idempotency_key` (a longer schema for every call), Codex exec
  commands that outlive their call are reported as native background jobs,
  Aether's MCP calls from Codex no longer time out after 300 s, a Codex wait
  in the same batch as a command settles for up to 500 ms, and agent
  replies carry `engine_alive` and `last_event_at`. Which of these, if any,
  raised Luna's tokens is not established by this run.
- Claude Code 2.1.309 and Codex 0.164.0 on both arms, as in r124.
- Two earlier attempts at this release are not the record. The first ran 7
  trials in a fresh private home, where concurrent Codex starts failed to
  create its state database and two Luna 1.2.4 trials failed before the
  model ran. The second ran 29 trials of an earlier candidate (`550dcb0b`)
  and was stopped when the pre-release review found a defect that changed
  the candidate.

## Luna cost follow-up

**Cause: chance, not Aether.** r125's Luna cost rise came from what the
model chose to do in each trial. Nothing Aether sends to Codex grew, so no
code changed.

- **The same requests on both binaries.** In r125b's Codex session logs,
  105 of the 106 solo pairs start with byte-identical model input once ids
  and paths are masked: the same tool list (34,090 bytes), the same system
  and developer text, and the same Aether assignment. Their first requests
  differ by at most 9 tokens, from the ids. The one exception, `query-8`,
  differs in Codex's own skills list (7,501 against 11,312 bytes), which
  varies between sessions of either binary. Every solo trial on both arms
  was one Codex turn, and Aether added no message or tool reply after the
  prompt.
- **Aether's MCP tools are not in Codex's request.** Codex 0.164 sends the
  model only its `exec` namespace and `clock`. That leaves out `delegate`'s
  new `idempotency_key`, whose descriptor `tool_surface.rs` bounds at 300
  bytes. New reply fields such as `engine_alive` and `last_event_at`, held
  native-wait replies and the lifted MCP timeout reach a Luna solo trial only
  through Aether tool calls, and these trials make none. Native
  background-job reporting only changes Aether's own bookkeeping.
- **The tokens are Codex's own figures.** For all 212 solo trials of
  r125b, the recorded tokens equal the sum of the Codex session's
  per-request usage on both binaries. The bench therefore measured what Codex
  sent; it did not miscount.
- **Large per-trial swings.** In a 6-task pilot of the same binaries, the
  candidate's `cron-8` made 20 requests where the old binary's made 9, with
  byte-identical input: the model just iterated longer on a spec corner.
  Swings like this, in both directions, explain r125's x1.14. r125b on the
  same binaries gave x0.98 and median tokens of 146k (candidate) against
  153k (old). Over both runs (220 pairs) the cost is x1.05 (x0.96 to x1.15).
