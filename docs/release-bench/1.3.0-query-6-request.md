# `query-6`: first model request comparison

The first serialized Claude request for `query-6` was captured on v1.2.11
and on the candidate built at `beb6aeeb65edbc9b3ab4e1384bb5654f37f8305e`.
Each binary ran the same task and release-bench setup with a fresh private
store and Claude Code 2.1.319. A local endpoint recorded the request body and
returned HTTP 400; it did not forward the request to the model. These
instrumented attempts are separate from the scored smoke run.

The only differences in the first payload were generated per trial:

| Field | Difference and cause |
| --- | --- |
| Task message | Task ID, short agent label and workspace/repository paths differ because the harness creates a new task and workspace for each trial; these are not changes introduced by a commit in this comparison. |
| Claude environment message | The primary working directory differs for the same reason. |
| Claude system prompt | The path to Claude's per-project file memory differs because it incorporates the working directory. The remaining system text matches. |
| Request metadata | The session ID differs; device and account IDs match. This is a new session, not a version change. |

After replacing those identifiers and paths and redacting the metadata user
ID, the two complete JSON bodies have the same SHA-256:
`6ef75029e7b220ef4b625d3541d30b6c63559549b93aae543c91680eb7f5937a`.
The sanitized bodies are retained with this item's evidence. Their three
system blocks, two messages and all 32 tool definitions and schemas match.
Both requests use `claude-haiku-5-5`, low effort, adaptive thinking, a
128,000-token output limit and the same context-management and streaming
settings. No Aether memory was injected into either fresh store. This
establishes equality of this captured first request after the stated
normalization, not equality of later calls or of populated-store behavior.

The relevant source changes since v1.2.11 do not produce an additional
payload difference in this trial:

- Memory retrieval and holdout (`b0713606`, `7914bb18`, `b1fcef23` and
  `c167cec8`) can change what a populated store injects. The default cutoff
  was restored to zero in `518aa2fb`; this item changes the default holdout
  to zero. Neither empty store had a memory to inject or withhold. Candidate
  admission exists from `51c87c09`, but defaults to `Immediate`, so candidate
  gating is not a default change in this build.
- The native tool watchdog and shell timeout setting (`57607b31`,
  `acce706e`) do not change this request's captured tools or limits. The
  watchdog stops a tool call outstanding for 15 minutes, beyond the smoke
  trial's 600-second limit.
- Structured results parsed from prose (`7509dbf1` and subsequent fixes)
  change completion handling after a response, not this first request.

The request comparison alone cannot explain a difference in coding outcomes.
The [earlier release report](1.3.0.md#what-the-haiku-losses-show) gives the
broader prior measurement and its limitations.
